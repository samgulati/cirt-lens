# Security and trust model

CIRT Lens is a multi-tenant portfolio security platform using synthetic telemetry. Public staging authenticates through Auth0 OIDC; the API verifies issuer, audience, signature, algorithm, and expiry, then enforces tenant and permission claims. Local PBKDF2 identities exist only for isolated development. Viewer, Analyst, Responder, and Administrator permissions are enforced in backend dependencies and covered by denial tests.

Detection and correlation are deterministic. Evidence confidence is a `/100` support heuristic, not probability or model certainty. Failed authentication and denied MFA prompts may provide context, but only successful authentication with impossible-travel or new-device evidence can causally support the post-authentication privileged-action rule.

The app never executes telemetry command lines or scans networks. Most response actions use an audited deterministic connector. Account disablement can call only one explicitly allowlisted identity in an isolated Auth0 development tenant. High-impact actions require a different approver, expire after 30 minutes, are consumed atomically on success, and preserve stable idempotency/provider request IDs. `CONTAINED` cannot be directly assigned through the ordinary incident-status API; it is derived only when all required playbook objectives execute. `RESOLVED` is an explicit analyst decision.

External AI is optional and backend-only. Only structured JSON claims with incident-owned evidence IDs are accepted. Malformed, plain-text, or unsupported output is retried once and replaced with deterministic local output. Citation validation constrains evidence ownership but does not prove interpretation. Analyst notes are also untrusted text; plain-text reports reproduce them verbatim and must not be rendered as trusted HTML.

The browser receives no API or Management API secret. Pydantic rejects extra telemetry fields, request sizes and pagination are bounded, SQLAlchemy parameterizes queries, CORS is allowlisted, and server exceptions do not expose stack traces. Every response and structured log carries a request ID. Detection rules, ingestion jobs, approvals, connector executions, events, incidents, search, reports, and audit records are tenant-scoped.
